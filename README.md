## Overview

Clarity is a personal productivity journal designed to help you track daily habits and reflect on weekly progress. Users can log goals, distractions, ratings, and notes, then view patterns through dashboard stats and weekly reporting. The app is built with a clean interface so entries and reports are easy to access across devices.

## Features

- User signup, email confirmation, and login with AWS Cognito
- Create journal entries with goals, distractions, ratings, mood, motivation, and notes
- View current and historical journal entries
- View historical AI-generated weekly reports
- Dashboard statistics and productivity analytics
- Historical mood vs. motivation visualization
- Scheduled weekly reports generated by cron, queued with RabbitMQ, and processed by a background worker
- AI-generated weekly summaries and recommendations with fallback generation
- Automatic session-expiry handling (401 redirects to login)
- Backend unit tests with automated GitHub Actions CI validation

## Architecture

The frontend is hosted on Netlify and communicates with an Express backend running on AWS EC2. Nginx reverse proxies requests to Dockerized API and background worker containers. The backend uses PostgreSQL (Neon), RabbitMQ (CloudAMQP), AWS Cognito for authentication, and the OpenAI API for AI-generated weekly reports.

## Purpose

Clarity is designed for people who want a consistent way to reflect on productivity and build healthier routines. Instead of storing scattered notes, users get one place to capture daily performance and review personalized weekly insights. It supports practical self-improvement by turning daily journaling into a structured weekly feedback loop.

## Local Development

1. Start local Postgres (optional if using Neon):
  - `docker compose up -d`
2. Copy and configure backend environment variables:
  - `cp backend/.env.example backend/.env`
3. Start the backend (first time or after schema changes, run migrations):
  - `cd backend && npm ci && npx prisma generate && npx prisma migrate dev && npm run dev`
  - When changing the schema, use `npx prisma migrate dev --name <description>` and commit `prisma/schema.prisma` plus the new folder under `prisma/migrations/`.
4. (Optional) Start the weekly-report worker in a second terminal:
  - `cd backend && npm run dev:worker:weekly-reports`
5. Start the frontend:
  - `cd frontend && npm ci && npm run dev`

Environment reference files:

- `backend/.env.example`
- `frontend/.env.example`

Note: `VITE_API_BASE` is required for production builds, but not for local `npm run dev`.

For saved weekly reports locally, also start RabbitMQ (`docker compose up -d rabbitmq`) and set `RABBITMQ_URL` in `backend/.env`. Preview Report works without the worker.

## Infrastructure

AWS infrastructure is managed using **Terraform**. The repository includes infrastructure-as-code definitions for the production EC2 instance, Cognito User Pool, Cognito App Client, Security Group, and Elastic IP. Existing production resources are imported into Terraform state to enable infrastructure management without recreating live services.

## Testing

The backend includes automated unit tests written with **Vitest** for core business logic and utility modules. Tests are executed automatically through **GitHub Actions** on pull requests to help catch regressions before code is merged.

Run the backend test suite:

```bash
cd backend
npm test
```

Generate a coverage report:

```bash
cd backend
npm run test:coverage
```


## RabbitMQ

Weekly report generation is decoupled using RabbitMQ. A scheduled publisher queues report-generation jobs, and a separate background worker processes those jobs asynchronously before saving completed reports to the database.

## Deployment

Production deployments follow a GitHub Actions workflow:

1. Open a Pull Request.
2. Backend tests and AI code review run automatically.
3. Merge into `main`.
4. GitHub Actions builds and publishes a Docker image to Docker Hub.
5. The production EC2 instance pulls the latest image and restarts the API and worker containers using Docker Compose.

Infrastructure is managed using Terraform, and deployment procedures are documented in the deployment runbook.
